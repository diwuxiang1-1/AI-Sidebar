## 0. 一句话概览

Microsoft Edge / Chrome **Manifest V3 扩展**(原生 HTML + CSS + JS,无框架、无构建、无 npm 依赖),
在浏览器侧边栏提供:BYK / 自带 API Key 的 AI 聊天、网页上下文、选中文字、
**网页翻译**、**网页资源清单**、**AI 修改网页(24 种动作 + 撤销/恢复)**、
**网页深度分析 + 媒体控制**、**聊天里直接改网页(结果与撤销都在聊天流里)**、
**同一服务商多 API Key 顺序轮询**、**锁定目标(多 Tab 独立操作)**、
**刷新后自动恢复网页修改**、以及**两级可选 AI 权限**(网页 Agent / 浏览器 Agent)。

**加载方式**:`edge://extensions` → 开发人员模式 → 加载解压缩的扩展 → 选择 `E:\AI-Sidebar`
**最低版本**:Chrome/Edge 116+
**改动代码后**:必须点「重新加载」,并**刷新已打开的网页**(旧内容脚本会失效)

## 3. 架构与不可破坏的约定 ⚠️

```
┌────────────────────────────────────────────────────────────────────┐
│  Sidebar 页面(sidebar.html)                                      │
│  脚本顺序:storage → provider → context → translate → webpatch →    │
│            permissions → browser-tools → sidebar   (顺序不可改!)   │
│  职责:UI 状态机 / 编排 / 调用 Provider                            │
└──────────┬──────────────────────────────────────┬─────────────────┘
           │ chrome.runtime.sendMessage            │ 直接 fetch
┌──────────▼──────────────────────────────────────┼─────────────────┐
│  background/service-worker.js(公共消息入口)                    │
│  · importScripts("/utils/permissions.js", "/utils/browser-tools.js")│
│  · 消息中转:侧边栏 → 当前活动标签页的内容脚本                     │
│  · 权限等级 1:chrome.scripting.executeScript({world:"MAIN"})       │
│  · 权限等级 2:调度 12 个 Browser Tool(白名单)                     │
└──────────┬──────────────────────────────────────┴─────────────────┘
           │ chrome.tabs.sendMessage
┌──────────▼────────────────────────────────────────────────────────┐
│  content/content.js(页面侧)                                      │
│  manifest 注入顺序:context.js → webpatch.js → content.js          │
│  网页读取 / 选中监听 / 翻译引擎 / 资源清单 / 修改执行器 / 深度分析 │
└───────────────────────────────────────────────────────────────────┘
```

### 必须遵守的 7 条

1. **`MSG` 常量三端手动同步**(`background` / `content` / `sidebar`)。
   当前共 **20 个消息类型**;各处出现的字符串数:
   `background` 21(含 1 个 storage key `ai-sidebar:default-model`)、`sidebar` 19、`content` 16。
   差额是设计使然,不是漏改:
   - `close` —— 只由后台发给侧边栏
   - `get-active-tab` —— 只由后台内部处理
   - `page-run-js` / `browser-tool` —— 由后台自己处理(不转发给内容脚本)
   - 其余 16 个 —— 三端一致,经后台转发到内容脚本

   核对命令(改完消息常量后可跑):
   `node dev/_count_msgs.js`

2. **脚本加载顺序不可调整**(见上图两处顺序),全部是经典脚本(非 ES module),靠全局作用域通信。

3. **`importScripts` 必须用以 `/` 开头的扩展根路径**。
   ⚠️ 第十轮曾因写成 `"utils/permissions.js"` 被解析成 `/background/utils/...` → 404 → **SW 整体启动失败 →
   所有网页功能同时瘫痪**。现已改为 `"/utils/..."` 并用 try/catch 包裹:
   **权限模块加载失败只降级权限能力,绝不能拖死消息中转。**

4. **网页上下文注入**:system 消息动态构造,**不写入会话 messages**。

5. **AI 代码只在网页主世界执行**(`world:"MAIN"`),在那里天然拿不到 `chrome.*`;
   任何地方都不使用 `eval` / `new Function` 执行 AI 返回的代码(注入函数内部包装网页代码除外,见 §5)。

6. **AI 修改网页只做局部修改**:不替换 `body` / `html`(除非用户明确要求整体重构),
   只改文本节点 `nodeValue` / 内联样式 / 专用 `<style id="ai-webpage-style">` / 消毒后的 HTML 片段。

7. **权限默认全关**,且**后台独立校验**(不信任侧边栏传来的标志)。

## 5. AI 修改网页:24 种动作

**结构化动作(14,可撤销)**
`add_css`(写专用样式表,默认 `!important`)、`set_style`(内联,自动驼峰→kebab)、
`hide` / `show`、`remove`、`set_text`、`set_title`、`set_attr`(白名单,`on*` 拒绝)、
`set_html` / `append_html` / `insert_html`(经 `<template>` 惰性解析 + 消毒)、
`create`、`move`、`set_media`(旧式媒体入口,仍兼容)

**媒体专用动作(8,可撤销)**
`media_play` / `media_pause` / `media_seek` / `media_set_rate` / `media_set_volume` /
`media_mute` / `media_unmute` / `media_toggle_controls`
→ 与 `set_media` **共用同一个执行核心** `wpMediaOperation`;
倍速允许 0.05–100(**不设人为上限**);执行后回报 `actualValue`,不达标则返回真实失败原因。

**需要权限的动作(2,不可撤销)**
`run_js`(等级 1,页面主世界执行网页代码)、`browser_tool`(等级 2,调用 12 个浏览器工具)

**元素定位**(可靠性顺序):`el_N` / `media_N` 内部编号(内存注册表,**不往网页写任何属性**)
→ CSS 选择器 → 文本匹配(`text` + 可选 `tag`)。
媒体目标额外支持 `video` / `audio` / 留空 → 按「正在播放 > 可见 > 主内容区 > 面积」自动挑选,
**无法确定时如实报错不猜**。

## 6. 已知问题与限制

| # | 问题 | 说明 / 处理 |
|---|------|-------------|
| 1 | Claude / Google 原生协议未适配 | 仅这两家不可靠;其余预设正常 |
| 2 | 错误气泡样式丢失 | 出错消息以 `role:"assistant"` 存会话,恢复历史后显示为普通气泡(纯视觉问题) |
| 3 | 费用价格表可能过时 | 硬编码 12 条公开参考价,仅算输入侧;查不到显示「无法估算费用」 |
| 4 | 修改网页面板**没有「停止」按钮** | 生成方案期间无法中断(UI 保持三按钮形态的设计取舍) |
| 5 | `run_js` / `browser_tool` 不可撤销 | 会在撤销/恢复提示中明确告知,不假装可回滚 |
| 6 | 网页 CSP 禁止 `unsafe-eval` 时 `run_js` 不可用 | 会返回真实错误并建议改用结构化动作 |
| 7 | 自定义播放器锁死倍速时只能失败 | 返回真实原因(例如「页面把倍速限制为 1 倍」) |
| 8 | 直播流不支持跳转 | `duration` 为未知时会标注;跳转失败会如实报告 |
| 9 | SPA 站内路由切换后资源页不自动刷新 | 需手动点「刷新」 |
| 10 | 浏览器内部页面(edge:// 等)不支持 | 所有网页能力都会返回友好错误 |
| 11 | 权限等级 2 会让扩展请求较多浏览器权限 | `tabs / history / cookies / downloads` 已声明,运行时由等级 2 把关 |
| 12 | 大页面深度分析可能卡顿 | 真实浏览器逐元素 `getComputedStyle` 有成本;已设规模上限 |
| 13 | `dev/` 下临时文件 | 不影响运行,可整体删除(测试脚本可留作回归) |
| 14 | 倍速锁定与别的倍速插件可能互相抢写 | 一个时间窗内抢写超过 5 次即**主动停手**,并在结果里说明「检测到其他脚本/播放器正在修改倍速」;不会无限互抢 |
| 15 | 多 Key 轮询只在**请求失败**时切换 | 不判断错误类型(401 / 429 / 超时都会换下一个);全部失败时返回**最后一个**真实错误 |
| 16 | 切换 Provider 会清空模型选择 | 设置页既有行为;换服务商后需要重新选模型才能保存 |
| 17 | 跨 Tab 操作需要权限等级 1 | 目标是浏览器当前**不显示**的锁定网页时,后台强制校验等级 1;未开启会明确拒绝而不是静默作用到当前页面 |
| 18 | Tab 管理 / 浏览器下载需要权限等级 2 | 下载、标签页、历史、Cookie 等一律走等级 2;未开启时返回「当前权限不足」而不是 JS 报错 |
| 19 | 锁定目标上限 8 个 | 超过会明确提示,不静默丢弃 |
| 20 | 已导航的目标默认拒绝执行 | 目标 Tab 跳到新地址后标记「需要重新确认」,避免把网页 B 当成网页 A;面板上点「重新确认此目标」恢复 |
| 21 | 刷新恢复依赖 URL 匹配 | 页面地址变了(或改成了别的页面)就不会恢复;恢复失败的项目会逐条如实报告原因 |
| 22 | **真实浏览器人工验证不完整** | 见 §8 清单;jsdom 无排版引擎与媒体管线,可见性/播放行为靠模拟 |

### 必做的手动验证清单(jsdom 覆盖不到)

1. 重新加载扩展 → 刷新网页 → 「当前网页」正常
2. 「网页资源」四类正常、打开/复制可用
3. 「网页翻译」翻译 + 恢复原文
4. 「修改网页」说「背景改深色,正文放大」→ 网页真的变;撤销;恢复
5. 普通 HTML5 视频说「**把当前视频调到 16 倍**」→ **眼睛确认播放速度真的变快**
6. blob 视频站(主流视频站)同样试 16 倍 → 不该出现「无法修改视频」
7. 多视频页面说「暂停视频」→ 作用于正在播放/最大的那个
8. 点「深度分析网页」→ 计数与媒体明细是否与页面相符
9. 设置页开启「权限等级 1」→ 说「用网页代码把页面主色调改成深色」→ 观察是否执行
10. 设置页开启「权限等级 2」→ 说「列出我的标签页」→ 观察 Browser Tool 是否被调用
11. 开着「当前网页」在聊天框说「把背景改成深色」→ 网页真的变,聊天里出现结果和 `[撤销]`;点撤销能还原
12. 普通聊天说「这个网页太亮了」→ **不应该**改网页,只回答并追问「需要我直接修改当前网页吗?」
13. 在网页上选中一段文字 → 输入框上方出现「已选中 N 字」chip;直接提问能用到这段文字
14. 设置页加两个 Key,把一个停用 → 保存后再进设置页,启用状态还在
15. 锁定网页 A → 切到网页 B → 说「把背景改成深色」→ **网页 A 变**,网页 B 不变
16. 同时锁定 A / B → 不点名直接下指令 → 应弹出「请选择操作目标」而不是猜一个
17. 关掉被锁定的 Tab → 目标栏应显示「目标网页已关闭」,继续下指令会被拒绝并说明原因
18. 锁定页跳转/换视频页(URL 变化)→ 标记「已导航」,点「重新确认此目标」后恢复
19. 改过网页后按 F5 → 页面应自动重新应用修改,聊天里出现恢复结果(几项成功/几项失败)
20. 设置里关掉等级 1 → 对非当前显示的锁定网页下指令 → 应提示「当前权限不足」而不是 JS 报错
